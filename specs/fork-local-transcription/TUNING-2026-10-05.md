Baseline: `88f3655`, `fix/local-transcription-latency`. Hardware: Apple M2 Pro,
32 GiB RAM, macOS 26.6.2, Xcode 26.6 (17F113). WhisperKit 0.16.0, existing
`openai_whisper-large-v3_turbo`, CPU/Neural Engine encoder and decoder.

## Decisions

- Saved this user's transcription language as English (`en`) in the existing
  `com.metawhisp.app` preference domain. Verified the persisted value. UI automation
  timed out, so live adoption by the already-running app is not confirmed; a
  restart guarantees a fresh read. No global default or multilingual behavior changed.
- Keep the 200ms paste settling delay, per the user's reliability preference.
- Keep segment timestamps. The small improvements below do not establish a
  consistent benefit across short dictation, and a larger quality corpus would
  be needed before changing decoding behavior. Meeting timestamps remain intact.
- Keep the SDK's 16-worker limit. Lower limits did not improve this workload.
- Do not add foreground scheduling yet: contention is measurable, but live
  meeting advice is disabled for this user (key absent, code default `false`).
- Incremental transcription remains deferred as the user's last resort.

## Method

`WhisperKitTuningTests` is an opt-in real-model experiment harness. It uses local
Samantha speech at 170 words/minute, downloaded model files, and one bounded
warm-up. No microphone, clipboard, history, or application preference writes.
All runs use English, no prompt tokens, existing retry/confidence-related decode
thresholds, and VAD. No production engine code was changed.

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
METAWHISP_TUNING=1 swift test -c release --filter WhisperKitTuningTests
```

Timestamp options alternate order across three runs per clip. Worker order is
reversed for the second pass. Concurrency comparisons use the same loaded kit;
the short foreground request starts 500ms after the longer background request.
Measurements include the SDK transcription call, not recording or pasting.
The desktop and existing app remained running; these are practical local
measurements, not isolated laboratory results or statistical confidence intervals.

## Timestamp results

Median seconds across three runs for each option:

| Clip | Timestamps on | Timestamps off | Reduction |
| --- | ---: | ---: | ---: |
| Short greeting | 0.973 | 0.912 | 0.061s |
| Meeting instruction | 1.672 | 1.479 | 0.193s |
| Decimal numbers | 2.053 | 1.985 | 0.068s |
| Two sentences, leading/trailing silence | 3.657 | 3.682 | -0.025s |

Output was identical between options for the first three clips. Both decoded
“lunch” as “launch” in the meeting instruction. Number formatting changed from
spoken words to digits correctly. On the silence-padded clip, timestamps-on
appended the spurious word “Ripped.” in all three runs; timestamps-off did not.
Both preserved the final real sentence. This is evidence worth retaining for a
future quality investigation, not proof of general hallucination reduction.
All these timestamp runs reported zero temperature fallbacks.

## Worker results

An 87.68-second, four-window recording produced identical transcripts for all
eight runs, retaining all 260 normalized words with one shared lunch/launch
substitution. Medians here are the averages of the two measured runs.

| Worker limit | Run 1 | Run 2 | Median |
| --- | ---: | ---: | ---: |
| 16 (current) | 19.973s | 19.898s | 19.935s |
| 4 | 19.854s | 20.065s | 19.960s |
| 2 | 24.619s | 23.287s | 23.953s |
| 1 | 22.357s | 22.088s | 22.222s |

Only four windows were available, so limits 4 and 16 exercise the same effective
parallelism. This does not settle performance for much longer meetings with more
than four windows. It does reject lowering the limit to 1 or 2 for this fixture.

## Background contention

The same 1.67-second greeting took median 0.981s alone and 1.477s with competing
background decoding: +0.496s, approximately 51%. All six foreground transcripts
were identical. This is a direct shared-engine overlap experiment, not a full
Meeting Copilot integration test. If live advice is enabled later, foreground
scheduling deserves investigation; a stage guard alone cannot preempt work that
has already started.
